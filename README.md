# 오늘의 서울 · 과제 4

서울 중구 기준 좌표의 현재 기온을 조회하고, 데이터가 도착하지 않아도 마지막 정상값과 일별 기록을 보존하는 정보판입니다. 공개 기록과 이 브라우저에서 조회한 기록을 구분하며, 다섯 가지 실패를 실제 기록에 영향을 주지 않고 합성 재생합니다.

주제는 작업을 시작하기 위한 **AI의 기본안**입니다. 사용자가 직접 선택한 주제로 기록하지 않습니다. Open-Meteo의 현재 기온은 기상 모델에 기반한 값이며, 특정 관측소의 실측값이 아닙니다.

[공개 정보판 열기](https://skt-aleph-project-4-dashboard.vercel.app) · [현재 배포 소스](https://github.com/PeterAhnn/SKT-ALEPH-Project-4-Dashboard/commit/37ac8914ad7a0e7c91ff79c91402c6c7ba7e3893)

## 실행

Node.js 22 이상에서 실행합니다. 별도 API 키가 필요하지 않습니다.

```sh
npm start
```

로컬 확인 주소: `http://localhost:8004`

```sh
npm test
npm run build
npm run collect
```

- `npm test`: 데이터 검사, 저장, 날짜 비교, 합성 실패 동작을 검사합니다.
- `npm run build`: `public/`의 정적 파일을 배포용 `dist/`에 복사합니다.
- `npm run collect`: 실행 시점에 공개 원천을 조회하여 실제 정상 기록을 `public/data/observations.json`에 보관합니다. 다른 KST 날짜에 다시 실행해야 두 날짜의 기록이 생깁니다. 수집 후 다시 빌드·배포해야 공개 화면에 반영됩니다.

GitHub Actions의 [일일 수집 작업](.github/workflows/daily.yml)을 연결했습니다. 매일 **09:20 KST 예정**이며 GitHub 상황에 따라 늦어질 수 있습니다. 정상 수집 결과와 원천 응답을 저장소에 반영하면 Vercel이 자동 배포합니다. [첫 수동 실행](https://github.com/PeterAhnn/SKT-ALEPH-Project-4-Dashboard/actions/runs/35671454459)은 성공했습니다. 다음 실제 날짜의 실행 성공과 공개 반영은 별도로 확인해야 합니다.

## 화면에서 확인할 것

1. 기온과 출처, 원천 기준 시각, 마지막 정상 수신 시각을 확인합니다.
2. `5종 한 번에 확인`으로 실패 설명과 기존 기록 보존을 확인합니다.
3. `공개 관찰 기록`에서 실제 날짜와 전날 대비 값을 확인합니다. 어제 기록이 없으면 변화값을 만들지 않습니다.

하루 대표값은 **해당 KST 수집 날짜의 첫 정상값**입니다. 전날 대비는 달력상 어제와 오늘의 대표값 차이이며 하루 평균이나 최고 기온의 차이가 아닙니다.

`이 브라우저 기록`은 방문자의 로컬 저장 자료입니다. 공개 관찰 기록과 합치거나 과제의 공통 관찰 증거로 세지 않습니다. 합성 실패의 예시 값도 실제 기록으로 저장하지 않습니다.

## 현재 준비 상태

- 실제 공개 관찰 2일 기록: **1 / 2일**. 2026-09-22 09:14:21 KST에 실제 원천에서 19.5°C를 수집했습니다. 원천 기준 시각은 09:00 KST이며, 두 번째 실제 날짜의 기록과 비교는 미완료입니다.
- 같은 날 후속 수집: GitHub Actions가 09:19:28 KST에 받은 마지막 정상값은 **20°C**입니다. 일별 대표값 19.5°C는 보존했으며 기록 날짜는 여전히 1일입니다.
- 자동 검사: 엔진 **11건**, 로컬 브라우저 **18건**, 공개 배포 브라우저 **18건** 통과. 공개 화면의 콘솔 오류는 0건입니다. 손상·미래 시각 저장 자료의 격리도 추가 확인했습니다. [검사 범위와 증거](docs/QA.md)를 참고하세요.
- 공개 접근·소스 일치: **확인 완료**. 새 격리 브라우저에서 결과물과 전체 커밋 소스를 인증 없이 열었으며 배포 파일 5개의 SHA-256이 해당 소스 커밋과 일치했습니다.
- 과제 상세 1~5단계 카드와 공식 합성 검사 꾸러미: **미수령·대조 대기**. 현재 실패 5종은 자체 초안입니다.
- 사용자의 직접 판단 3줄: **확인 대기**.

구현·자동 검사·실제 날짜 관찰·공개 접근 검증은 각각 구분합니다. 기다린 시간은 과제의 작업시간으로 계산하지 않습니다.
