# 대구 날씨 서비스 추가 API 선정

> 최신 사용자 결정(2026-09-23): **공공데이터포털 인증키만 사용하며 API허브 별도 인증키가 필요한 기능은 제외한다.** 아래는 폭넓게 비교한 조사 기록이며 모두 구현하는 계획이 아니다. 최종 범위는 [공공데이터 API 계획](PUBLIC-API-PLAN.md)의 확정 범위를 따른다. 도로위험·도로관측·AWS·산악·고해상도 격자의 API허브 연계안은 이번 과제에서 채택하지 않는다. 도로 기능은 포털 CCTV 기반 도로날씨만 선택 후보로 남긴다.

2026-09-23 조사. 기존 단기·중기·특보·생활지수·ASOS·일기도·대기질 선정 범위를 넓혔다. 공공데이터포털에서 ‘기상청’ 검색 후 오픈API 탭의 11개 페이지, 101개 고유 목록을 확인했다. 이 중 명칭이 기상청으로 시작하는 목록은 86개다. 검색 결과에는 다른 기관 자료 및 동일 자료의 포털/API허브 경로가 함께 있으므로 이를 86개 독립 기능이나 모든 기관의 기상 API 총수로 해석하지 않는다. 주요 후보의 상세 명세와 API허브 교통안전 설명, 도로망 보조 자료를 추가 확인했다.

이 문서는 제품 관점의 추천이다. 사용자 키로 실제 응답을 받거나 새로운 기능을 배포하지 않았다. 확인한 목록은 [조사 목록](verification/weather-api-catalog.json)에 보관한다.

레이더와 위성은 서로 다른 목적을 가진다. 서비스 사용자가 ‘어디에 비가 오는지’를 보려면 레이더를 먼저 제공하고, 위성은 넓은 구름 흐름을 보는 선택 화면으로 둔다. 원본 수치자료·경량화 자료보다 이미지 조회 API로 첫 버전을 구성하면 구현 범위를 줄일 수 있다.

| --- | --- | --- |
| CCTV 기반 날씨 판별 | [CCTV 기반 도로날씨](https://www.data.go.kr/data/15057966/openapi.do) | CCTV 지점 또는 표준노드링크별 비·눈·안개 등의 판별. CCTV 동영상 스트리밍 API가 아님. API허브 설명은 고속도로 지정 노선, 야간 판별 성능 저하로 주간 활용 권장 |

| 도로 위치와 구간 연결 | [국토교통부 표준노드링크](https://www.data.go.kr/data/15025526/fileData.do) | 도로 형상과 구간 ID를 연결하는 SHP 파일 자료. 날씨·교통 소통상태 자체가 아니며 API로 잘못 소개하지 않음 |

[API허브 교통안전 명세](https://apihub.kma.go.kr/apiList.do?seqApi=971&seqApiSub=293)에서 도로위험정보의 대상 노선과 계절, UTC를 확인했다. 도로기상 관측 조회는 KST이고 조회용 내부 노선 번호 체계가 위험정보의 노선 번호 체계와 다르므로 같은 번호를 그대로 재사용하지 않는다. 경부·중부내륙·무안광주대구·중앙선 등의 실제 대구 주변 제공 구간을 확인한 뒤 시작한다.

도로망 지도는 ‘날씨를 도로에 표시하기 위한 바탕’이다. 도로위험기상이 없는 구간을 안전한 도로로 칠하거나, CCTV 날씨명만으로 노면 결빙을 확정하지 않는다. 계절상 미제공·관측소 미설치·발표 없음·통신 실패를 각각 설명한다.

## 화면과 연결 순서

1. **오늘**: 기존 현재·예보에 영향예보와 꽃가루를 필요한 때만 표시한다.
2. **날씨지도**: 레이더를 기본 화면으로 두고 위성·낙뢰를 전환한다. 태풍 발생 시 공식 경로를 추가한다.
3. **이동·야외**: 제공 구간이 검증된 도로날씨·도로위험과 산악예보를 표시한다.
4. **기록·검증**: 과제 기능은 기존 공개 검증 화면에 유지한다.

권장 순서는 레이더 → 영향예보 → 위성·낙뢰 → 도로기상이다. 꽃가루·태풍은 해당 계절과 상황에 맞춰 추가한다. AWS·고해상도 지도는 지역 매핑과 자료 처리 준비 후 확장한다. 해양·항공·농업 전용 자료, 고층관측·수치모델 원자료는 목록 검토 대상이었지만 대구 일상 날씨의 첫 확장에서는 후순위로 둔다.

## 인증과 검증 범위

레이더영상·위성영상·낙뢰분포도·영향예보·꽃가루·태풍·CCTV 기반 도로날씨는 포털 REST 서비스이다. 도로위험·도로관측·AWS·산악·고해상도 격자는 포털에 LINK형으로 등록되어 있으며 제공기관의 실제 이용신청·호출 규칙을 확인해야 한다. API허브 호출 예시는 authKey를 사용한다. 공공데이터포털의 serviceKey와 같은 키라고 가정하지 않는다.

[API허브 이용안내](https://apihub.kma.go.kr/apiInfo.do)는 API허브 회원가입 후 인증키 발급을 요구한다. 이는 개발자의 원천 이용 절차이며 공개 날씨 서비스를 보는 방문자에게 로그인을 요구한다는 뜻이 아니다.

과제 카드 2가 허용한 서버 환경변수 방식으로 연결한다. 원문 키·키가 포함된 URL을 공개 코드, 응답, 오류, 로그, 원자료 증거에 넣지 않는다. 캐시와 출처 시각을 관리하되 자료를 수신하지 못한 상태를 정상이나 안전으로 표시하지 않는다. 현재 조사로 실제 응답 성공·제공 지점·운영 승인까지 확인한 것은 아니다.
