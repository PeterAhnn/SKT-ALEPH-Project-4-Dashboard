# 대구 날씨 서비스에 사용할 공공데이터 API

공공데이터포털 공식 서비스 상세와 명세를 2026-09-22~23에 확인했습니다. 이 문서는 선정안과 진행 상태입니다. 2026-09-23 서버 연동으로 실황·단기·중기·특보·대기질의 실제 응답을 확인했습니다. 에어코리아는 간헐적 시간초과가 있습니다. 상세는 [연동 검사](PORTAL-INTEGRATION.md)를 참고하세요.

위성·레이더·낙뢰·도로기상·산악·꽃가루 등 기존 후보 밖의 조사는 [추가 API 선정](ADDITIONAL-WEATHER-APIS.md)에 정리했습니다. ‘기상청’ 검색 오픈API 101개 목록을 검토하고 주요 후보 상세 명세를 확인했습니다.

## 확정 범위 — 공공데이터포털 인증키만 사용

2026-09-23 사용자 결정: 과제 규모를 유지하고 별도 가입·키 발급을 늘리지 않는다. **기상청 API허브의 별도 인증키가 필요한 서비스는 사용하지 않는다.** 아래 조사 목록보다 이 결정이 우선한다.

- 기본 기능: 공공데이터포털의 단기예보·중기예보·기상특보.
- 우선 추가: 포털 REST 방식의 레이더영상·영향예보·위성영상·낙뢰분포도. 영상은 한 영역에서 전환하여 메인 카드를 늘리지 않는다.
- 선택 기능: 포털 REST 방식의 생활기상지수·꽃가루·태풍·CCTV 기반 도로날씨. 승인된 API를 모두 구현해야 한다는 뜻은 아니다.
- 제외: API허브 키가 필요한 도로위험기상·도로기상관측·AWS·산악예보·고해상도 격자 등 LINK형 후보. 도로 기능이 필요하면 포털 CCTV 기반 도로날씨만 검토한다.
- 대기질 포함: 에어코리아 대기오염정보의 미세먼지(PM10)·초미세먼지(PM2.5)를 보조 정보로 연결한다. 실제 사용 가능 상태와 응답을 확인한 뒤 공개한다. 별도 측정소 API를 필수로 추가하지 않고 제공 응답의 측정소명·측정시각을 표시한다.

서비스별 활용승인과 실제 응답 성공은 별개다. 기존 포털 키를 서버 환경변수로 연결하고 실제 응답이 확인된 기능만 공개한다. API허브 호출 경로로 우회하거나 새 인증키 발급을 요구하지 않는다. 메인 원천은 기상청·에어코리아이며 검증 화면의 기존 Open-Meteo 기록은 별도 보존한다. 개인 계정의 신청번호·인증키·화면 캡처는 공개 문서에 보관하지 않는다.

## 확인한 호출 경로와 주의점

- 단기: `VilageFcstInfoService_2.0`의 `getUltraSrtNcst`, `getUltraSrtFcst`, `getVilageFcst`. 날짜·발표 시각과 `nx`, `ny`가 필요합니다.
- 중기: `MidFcstInfoService`의 `getMidLandFcst`, `getMidTa`, `getMidFcst`. 예보구역 코드와 발표 시각을 사용합니다. 단기와 중기의 제공 기간 설명은 각 최신 명세를 따르고 겹치는 날짜의 우선순위를 정합니다.
- 특보: `WthrWrnInfoService/getPwnStatus`의 현재 특보현황을 우선합니다. `getWthrWrnList`는 발표 목록 기능입니다. 특보구역 명칭·코드 매핑을 검증한 뒤 지역 필터를 적용합니다.
- 생활: 포털 표시명은 4.0이지만 확인한 명세의 경로는 `LivingWthrIdxServiceV5`, 기능은 `getUVIdxV5`, `getAirDiffusionIdxV5`입니다. 과거 블로그의 V3/V4 코드를 그대로 복사하지 않습니다.
- ASOS: `AsosHourlyInfoService/getWthrDataList`, `stnIds` 관측소와 조회 기간을 사용합니다.
- 일기도: `WthrChartInfoService/getSurfaceChart`, 지상코드와 날짜로 파일 정보를 조회합니다. 자료 이미지와 수치 예보를 혼동하지 않습니다.
- 대기질: `ArpltnInforInqireSvc`, 측정소 연결은 `MsrstnInfoInqireSvc`. 명세상 개발 트래픽 500이며 운영단계는 심의승인입니다. 기상청 서비스와 동일한 승인·호출량이라고 가정하지 않습니다.

기상청 API허브와 공공데이터포털은 인증·요청 경로가 다릅니다. 이번에는 공공데이터포털의 `serviceKey` 방식만 사용하고 API허브의 `authKey` 방식은 제외합니다. 키 보유와 서비스별 활용승인, 실제 응답 확인은 구분합니다.

## 화면 구성

1. 지역 선택과 현재 날씨. 해당 지역에 발효 중인 특보가 있으면 이 영역 가까이 표시합니다.
2. 앞으로 비가 오는지, 시간별·단기예보, 중기 전망을 순서대로 배치합니다.
3. 레이더·위성·낙뢰를 한 영상 영역에서 전환하고 영향예보는 발표된 때만 강조합니다. 미세먼지·초미세먼지는 보조 정보로, 생활지수·CCTV 등은 필요한 기능만 선택합니다.
4. 공식 합성 실패, 원자료·해시 대조, 실제 이틀 기록은 로그인 없는 `review.html`에 유지합니다.

## 키와 기존 과제 기록

과제 카드 2는 키가 없는 출처 또는 **서버 쪽 환경변수로만 호출**하는 방식을 허용합니다. 키 사용 자체가 금지된 조건은 아닙니다. 방문자는 로그인하지 않고 서비스를 이용합니다.

브라우저 → 우리 서버 → 공공데이터 API 순서로 호출하고 키는 서버 환경변수에 둡니다. 서버 응답·오류·공개 원자료·출처 URL·로그에 키를 포함하지 않습니다. 디코딩 키를 저장하고 URL을 구성할 때 한 번 인코딩합니다. 서비스별 다른 키는 서버 설정에서 구분합니다.

현재 보존 중인 Open-Meteo 고정지점의 실제 두 날짜 자료는 그대로 둡니다. 기상청·새 지역 데이터는 원천·지역·단위별로 별도 저장하여 서로 다른 관측소나 모델의 값을 어제 대비로 섞지 않습니다. 플랫폼 봉인 영수증은 실제 과제 화면에서 별도로 확인해야 합니다.
