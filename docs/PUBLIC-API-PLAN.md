# 대구 날씨 서비스에 사용할 공공데이터 API

공공데이터포털 공식 서비스 상세와 명세를 2026-09-22~23에 확인했습니다. 이 문서는 선정안입니다. 사용자 인증키로 실제 응답을 받은 연동 완료 기록은 아닙니다. 현재 배포 원천은 Open-Meteo이며 기상청 데이터로 표시하지 않습니다.

## 먼저 연결할 정보

| 우선순위 | 공공데이터포털 서비스 | 서비스에 넣을 기능 | 표시할 때 지킬 기준 |
| --- | --- | --- | --- |
| 1 | [기상청 단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do) | 읍면동 선택, 현재 기온·강수·습도·바람, 초단기·단기예보 | 읍면동을 공식 격자 좌표에 연결. 같은 격자를 공유하는 동도 있으며 동마다 관측소가 있다는 뜻은 아님 |
| 2 | [기상청 기상특보 조회서비스](https://www.data.go.kr/data/15000415/openapi.do) | 해당 지역 특보·예비특보, 발표·발효 시각 | 현재 현황 조회를 사용. 과거 발표 목록이 비어 있거나 요청이 실패한 것을 ‘특보 없음’으로 표시하지 않음 |
| 3 | [기상청 중기예보 조회서비스](https://www.data.go.kr/data/15059468/openapi.do) | 며칠 뒤 날씨·최저/최고 기온 전망 | 육상 날씨는 권역, 기온은 도시 예보구역 단위. 읍면동 정밀예보처럼 표현하지 않음 |
| 4 | [에어코리아 대기오염정보](https://www.data.go.kr/data/15073861/openapi.do) | PM10·PM2.5·오존과 대기질 예보 | 기상청이 아닌 한국환경공단 자료. 실제 측정소 이름과 자료 시각 표시. 결측·점검을 0이나 좋음으로 처리하지 않음 |

현재·초단기·단기는 단기예보 서비스의 서로 다른 상세 기능을 사용합니다. 날씨, 강수확률, 기온 자료를 시간과 격자 기준으로 맞춥니다. 발표 직후 아직 자료가 생성되지 않은 경우에는 이전 발표 자료임을 표시합니다.

## 보조·상세 화면에 넣을 정보

| 정보 | 공공데이터포털 서비스 | 배치와 이유 |
| --- | --- | --- |
| 자외선·대기정체지수 | [기상청 생활기상지수](https://www.data.go.kr/data/15085288/openapi.do) | 자외선을 작은 생활 카드로 제공. 대기정체지수는 미세먼지 측정값과 구분 |
| 관측 기록 | [기상청 지상(종관, ASOS) 시간자료](https://www.data.go.kr/data/15057210/openapi.do) | 관측소별 과거 기록·추세 상세. 해당 API의 종료일 설명은 전일(D-1)까지 제공이므로 현재 기온용으로 사용하지 않음 |
| 일기도 | [기상청 일기도 조회서비스](https://www.data.go.kr/data/15043562/openapi.do) | 별도 ‘기상자료’ 화면에서 지상·보조 일기도 보기. GIF 이미지의 분석 시각·UTC/KST를 표시 |
| 측정소 연결 | [에어코리아 측정소정보](https://www.data.go.kr/data/15073877/openapi.do) | 대기질 카드에 필요한 측정소 목록·위치 연결. 자체 정보 카드로 메인 화면을 늘리지 않음 |

종관관측은 관측소별 값이고 일기도는 넓은 영역의 분석 자료입니다. 선택한 동의 자체 관측값처럼 표시하지 않습니다. 일상적인 날씨 확인에서는 일기도보다 특보와 강수, 미세먼지가 우선입니다.

## 확인한 호출 경로와 주의점

- 단기: `VilageFcstInfoService_2.0`의 `getUltraSrtNcst`, `getUltraSrtFcst`, `getVilageFcst`. 날짜·발표 시각과 `nx`, `ny`가 필요합니다.
- 중기: `MidFcstInfoService`의 `getMidLandFcst`, `getMidTa`, `getMidFcst`. 예보구역 코드와 발표 시각을 사용합니다. 단기와 중기의 제공 기간 설명은 각 최신 명세를 따르고 겹치는 날짜의 우선순위를 정합니다.
- 특보: `WthrWrnInfoService/getPwnStatus`의 현재 특보현황을 우선합니다. `getWthrWrnList`는 발표 목록 기능입니다. 특보구역 명칭·코드 매핑을 검증한 뒤 지역 필터를 적용합니다.
- 생활: 포털 표시명은 4.0이지만 확인한 명세의 경로는 `LivingWthrIdxServiceV5`, 기능은 `getUVIdxV5`, `getAirDiffusionIdxV5`입니다. 과거 블로그의 V3/V4 코드를 그대로 복사하지 않습니다.
- ASOS: `AsosHourlyInfoService/getWthrDataList`, `stnIds` 관측소와 조회 기간을 사용합니다.
- 일기도: `WthrChartInfoService/getSurfaceChart`, 지상코드와 날짜로 파일 정보를 조회합니다. 자료 이미지와 수치 예보를 혼동하지 않습니다.
- 대기질: `ArpltnInforInqireSvc`, 측정소 연결은 `MsrstnInfoInqireSvc`. 명세상 개발 트래픽 500이며 운영단계는 심의승인입니다. 기상청 서비스와 동일한 승인·호출량이라고 가정하지 않습니다.

기상청 API허브와 공공데이터포털은 인증·요청 경로가 다릅니다. 사용자가 보유한 공공데이터포털 키로 API허브의 `authKey` 호출이 된다고 가정하지 않습니다. 키 보유와 서비스별 활용승인 상태는 별개입니다.

## 화면 구성

1. 지역 선택과 현재 날씨. 해당 지역에 발효 중인 특보가 있으면 이 영역 가까이 표시합니다.
2. 앞으로 비가 오는지, 시간별·단기예보, 중기 전망을 순서대로 배치합니다.
3. 미세먼지·자외선은 보조 정보로 묶고 일기도·종관관측은 상세 메뉴에서 엽니다.
4. 공식 합성 실패, 원자료·해시 대조, 실제 이틀 기록은 로그인 없는 `review.html`에 유지합니다.

## 키와 기존 과제 기록

과제 카드 2는 키가 없는 출처 또는 **서버 쪽 환경변수로만 호출**하는 방식을 허용합니다. 키 사용 자체가 금지된 조건은 아닙니다. 방문자는 로그인하지 않고 서비스를 이용합니다.

브라우저 → 우리 서버 → 공공데이터 API 순서로 호출하고 키는 서버 환경변수에 둡니다. 서버 응답·오류·공개 원자료·출처 URL·로그에 키를 포함하지 않습니다. 디코딩 키를 저장하고 URL을 구성할 때 한 번 인코딩합니다. 서비스별 다른 키는 서버 설정에서 구분합니다.

현재 보존 중인 Open-Meteo 고정지점의 실제 두 날짜 자료는 그대로 둡니다. 기상청·새 지역 데이터는 원천·지역·단위별로 별도 저장하여 서로 다른 관측소나 모델의 값을 어제 대비로 섞지 않습니다. 플랫폼 봉인 영수증은 실제 과제 화면에서 별도로 확인해야 합니다.
