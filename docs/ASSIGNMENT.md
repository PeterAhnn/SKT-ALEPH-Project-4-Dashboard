# 과제 4 · 오늘의 진짜 정보판 — 데이터가 안 올 때

사용자 확정 주제: **대구 실시간 날씨 및 예보 현황판**. 계획 작업시간 6~7시간, 서로 다른 실제 KST 날짜의 관찰 2건이 필요합니다. 기다린 시간은 작업시간에 넣지 않습니다.

실제 공개 원천의 값과 맥락을 보여 주고 외부 실패 다섯 종류를 합성 재생합니다. 실패해도 마지막 정상값과 일별 기록을 보존하며 실제 두 날짜의 값으로 변화를 다시 계산합니다. 개인정보·비밀값 없이 공개 결과물 주소·소스 주소·확인 4줄·판단 3줄을 제출합니다. 날짜·해시·과제 버전은 플랫폼이 기록합니다.

## 5단계와 구현

24시간·7일 예보와 현재 습도·체감온도·바람·강수는 보조 정보입니다. 매일 기록·비교하는 주된 값은 **현재 지상 2m 기온** 한 가지이며 예보나 최고·최저값으로 대체하지 않습니다. 모델 기반 현재 값이므로 관측소 실측으로 설명하지 않습니다.

사용자 카드의 공개 접근 요구사항을 정본 registry는 계정 생성·로그인·인증·초대·비밀번호·OAuth·CAPTCHA로 나누고 URL 형식 C34~C35를 별도 판정합니다. 관측하지 않은 조건을 추정해 통과로 표시하지 않습니다.

공식 계약의 C22~C24 판정은 플랫폼 `제출정보.json.과정영수증[]`의 canonical kind `t04_day` **정확히 2건**을 사용합니다. `server_created_at`을 Asia/Seoul로 변환한 날짜가 서로 달라야 하며 payload의 `source_url`, `source_observed_at`, `normalized_value`, `unit`을 앱의 보관값·화면값과 대조합니다. 영수증 시간순의 두 값으로 변화값도 재계산합니다. 앱의 `review-evidence.json`과 합성 D1/D2는 플랫폼 봉인 영수증이 아닙니다. 별도 인증 파일이나 증거 ZIP을 손으로 만들 필요는 없습니다. 사용자는 플랫폼 날짜 기록 화면을 아직 확인하지 않았다고 답했으므로 영수증 존재·내용은 미확인 상태입니다.
