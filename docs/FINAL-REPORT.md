# 과제 4 검증 보고서

대구 실시간 날씨 및 예보 현황판 · 2026-09-28 KST

## 1. 결론

앱의 기능과 공개 검증에서 발견된 과제 미구현 항목은 없다. 다만 **공식 35개 기준의 전 항목 충족을 확정하지는 않는다.** C22~C24의 앱 자료는 충족하지만, 공식 검사 계약에서 쓰는 플랫폼 과정 기록은 첫날 1개로 확인되어 해당 플랫폼 증거 요건은 미충족이다. 사용자는 앱의 기록·검증 화면에 있는 두 날짜와 값을 확인했다. 앱에 보존된 이틀 자료의 날짜·원문·값·변화는 자동 검증을 통과했다.

이 보고서는 제출 전 자체 검증 결과이며 공식 채점·강사 승인 또는 학생의 직접 시험 기록을 대신하지 않는다. 28개 항목은 공개 접근/구현/검사 범위에서 확인, 4개는 제출 문안 준비, 3개는 앱 검증 완료·플랫폼 둘째 날짜 대기으로 구분했다. 계획 시간은 안내의 6~7시간이며 실제 작업시간은 측정하지 않아 기재하지 않았다.

## 4. 실패 재생과 복구

공식 package ID는 aleph-t04-real-information-board-public-contract-v2, public contract 2.0.0, fixture contract 1.1.0이다. 변경하지 않은 공식 fixture만 합성 재생에 사용한다.

| 실패 | 표시 상태 | 다음 행동 |
| --- | --- | --- |
| 느린 응답 | stale / timeout | 잠시 기다린 뒤 재시도 |
| 외부 원천 401 | stale / auth | 원천 접근 정책 확인 후 재시도 |
| 호출 제한 429 | stale / rate_limit | 안내된 대기 시간 뒤 재시도 |
| 오프라인 | stale / offline | 인터넷 연결 확인 후 재시도 |
| 응답 형식 변경 | stale / schema_error | 응답 형식과 변환 규칙 확인 |

모든 실패에서 마지막 정상값 105와 같은 날 기록 한 건을 유지한다. RECOVER-D2 후 120, fresh/none, 날짜별 기록 정확히 두 건, 변화 +15를 확인했다. 같은 D1을 세 번 재생해도 한 행이며, D2 복구를 반복해도 두 행을 유지했다. 이 숫자와 날짜는 합성이며 실제 이틀 자료를 대신하지 않는다.

## 5. 실제 이틀 자료

| KST 조회 날짜·시각 | 원천 시각 KST | 보관 기온 | 원천 |
| --- | --- | --- | --- |
| 2026-09-22 09:36:25.628 | 09:30 | 21.9°C | Open-Meteo 대구 |
| 2026-09-23 13:45:35.713 | 13:45 | 25.8°C | Open-Meteo 대구 |

25.8 - 21.9 = **+3.9°C**. 원문 해시와 각 자료의 sourceUrl·observedAt·fetchedAt·value·unit을 보관값 및 화면과 대조했다. 서로 다른 수신 시각의 두 값이며 하루 평균이나 같은 시각의 비교가 아니다. 고정 심사용 자료는 정확히 두 건이고, 운영 중 매일 누적되는 최근값 표는 별도이다.

사용자 확인: 앱의 기록·검증 화면에 두 날짜와 값이 있음. 2026-09-28 로그인된 ALEPH T04 화면의 선택 과정 기록을 펼쳐 처음에는 기록 0개를 확인했고, 사용자 요청에 따라 9월 28일 실제 최신 조회값 24.7°C(원천 17:00 KST)를 입력해 첫날 기록 1개 저장을 확인했다. 화면은 이 기록 없이도 제출·강사 승인·마스터 승인이 가능하며 후행 평가의 보조 자료라고 설명한다. 동시에 실제 이틀 판정은 플랫폼 Asia/Seoul 서버 날짜를 사용한다고 명시한다. 따라서 앱 기록과 플랫폼 과정 기록을 혼동하지 않으며, 공식 계약의 플랫폼 증거 요건은 현재 미충족으로 남긴다.

## 6. 비밀값과 개인정보

공공데이터포털 키와 API허브 키는 Vercel 서버 환경변수에서만 사용한다. 브라우저는 허용된 /api/weather 경로를 호출하며 상류 인증 URL/본문을 전달하지 않는다. 공개 소스와 Git 이력에서 주요 토큰 패턴, 로컬 비밀 설정 값과 비교한 결과 탐지 0건이다. Vercel Secret 키 원문은 내려받을 수 없어 해당 원문과 전 파일의 직접 비교를 수행했다고 주장하지 않는다. 서버의 응답 검사와 자동 검사로 키 반환을 방지한다.

현재 위치는 버튼을 눌렀을 때만 요청하고 브라우저 내에서 대표 좌표와 비교한다. 개인 좌표를 저장·전송·제출하지 않으며 선택한 공개 지역 ID만 저장한다. 공개 보고서에는 로그인된 플랫폼의 리추얼·출석·계정 화면이나 개인 기록을 포함하지 않았다.

## 8. 제출 준비 및 남은 확인

SUBMISSION-COPY.txt의 결과물 URL·고정 소스 URL·확인 4줄·판단 3줄을 플랫폼의 해당 칸에 입력한다. PDF 보고서는 보관용이며 플랫폼의 필수 제출 항목으로 추가하지 않는다. 날짜·해시·과제 버전은 플랫폼이 기록한다.

현재 자료로 제출은 가능하다. 공식 계약의 플랫폼 증거까지 충족하려면 서로 다른 실제 KST 날짜에 공개 원천을 조회하고 선택 과정 기록을 각각 남긴 뒤 그 두 실제 자료와 변화값을 대조해야 한다. 과거 앱 자료를 오늘 입력해도 과거 서버 날짜가 되지 않는다. 기존 날짜·값을 조작하거나 지금 두 번 입력해 이틀로 대신하지 않는다. 9월 28일 첫날 과정 기록은 생성했다. 둘째 날은 9월 29일 이후 실제 조회로 이어간다. 최종 과제 제출 버튼은 누르지 않았다.
